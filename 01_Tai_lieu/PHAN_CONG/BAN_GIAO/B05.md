## Phạm vi triển khai

1. Danh mục cơ sở giữ sáu form, quyền server, tạo/sửa/version/validation. Tải lại bản ghi trên trang lấy version mới.
   Bộ chọn tham chiếu có tìm mã/tên, keyset 50 dòng/trang, Enter/Tab/Escape, giữ ID ngoài trang/đã ngừng dùng.
   Cây vị trí dựng từ trang hiện tại và các tổ tiên, hiển thị kho/Zone/Rack/Bin. Bộ chọn cha lọc theo kho.
2. Tab con **Quy đổi / barcode / giá**: tạo revision UOM với version sản phẩm; barcode giữ số 0 đầu,
   không tái gán mã/quy cách, cho ngừng dùng; giá append theo ngày/nguồn và phân biệt quyền ghi GLOBAL với đọc tại kho.
   Decimal gửi nguyên chuỗi. API quyết định các bất biến; không thêm rule tồn/giá ở client.
3. Tab con **Chủ hàng / ký gửi**: form owner/hợp đồng có version/nguồn/ngày, ngừng dùng, owner hệ thống chỉ đọc.
   Tra `stock-ownership` hiển thị physical/owned/consigned/unclassified cùng từng owner/đối tác; không cộng khác SKU/UOM.
4. Tra serial và ghi/đính chính/rút chứng cứ bằng revision append-only. Receipt move/version lấy từ GET;
   thiếu nguồn không cho ghi; không suy thời hạn. Rút chứng cứ gửi null ngày/nguồn kèm lý do, giữ lịch sử.
5. HTTP qua worker; Tk cập nhật từ drain trên main thread. Sequence + session generation loại phản hồi cũ.
   Đổi kho/phiên, đăng xuất hoặc bị từ chối quyền xóa dữ liệu; lệnh mất ACK giữ payload/key, chỉ retry chủ động,
   khôi phục trong RAM theo đúng actor khi reload/đăng nhập lại cùng process.

## Contract và ranh giới tích hợp

Không đổi API, DTO, policy, event, consumer hoặc migration; PostgreSQL 001–010 và SQLite 001–002 nguyên trạng.
Không thêm dependency Python. Dùng interpreter venv điều phối chỉ đọc với `PYTHONPATH=.` tại worktree B05.

Các endpoint dùng trực tiếp:

| Nhóm | Endpoint và payload |
| --- | --- |
| Danh mục | GET/POST/PUT `master/{uoms,categories,products,partners,warehouses,locations,barcodes,stock-owners,consignment-agreements}`; GET detail; `q`, `limit`, `after`, `active`, `warehouse_id`; ghi dùng `reason`, PUT thêm `expected_version` |
| Quy đổi | GET/POST `master/product-uoms`; POST `product_id`, `uom_id`, `factor`, `expected_product_version`, `reason` |
| Giá | GET/POST `master/products/{id}/prices`; GET `warehouse_id`, paging; POST `effective_on`, `amount`, `currency`, `source`; ACK không lộ giá |
| Owner balance | GET `stock-ownership` với `warehouse_id`, `location_id`, `stock_item_id` |
| Serial | GET `serials/lookup` với kho, mã, SKU tùy chọn; POST `serials/{id}/warranty-records` với `expected_version`, `receipt_move_id`, ngày/nguồn nullable, `reason` |
| Quyền | GET `warehouses/{id}/permissions` khi tra serial; kho chọn từ snapshot đăng nhập |

Mọi lệnh ghi gửi `Idempotency-Key`. Hợp đồng ký gửi chỉ quản trị metadata theo API hiện có; policy tiêu thụ/chuyển
quyền và nhận ký gửi theo workflow thuộc B09. Không tự dựng policy hoặc API giả.

File chung chỉ đổi `apps/desktop/views/shell.py`: thêm các tab con trong **Danh mục**, hook session/poll/close/finish.
Vẫn tám mục điều hướng cấp chính; không sửa UI admin B04 hoặc orders B15. Presenter danh mục được mở rộng để
dùng chung bộ chọn, giá và owner. File mới `catalog_lookup.py`, `master_details.py`, ownership view/presenter.
Hướng dẫn module cập nhật ở [MASTER_DATA](../../MASTER_DATA.md) và [TRACEABILITY](../../TRACEABILITY.md).
