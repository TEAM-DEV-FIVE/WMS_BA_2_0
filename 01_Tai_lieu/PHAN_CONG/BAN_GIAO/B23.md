## Contract, migration và file chung

`GET /api/v1/health`, `GET /api/v1/ready` thành công thêm hai header:

```text
X-WMS-API-Protocol: 1
X-WMS-Recovery-Protocol: lookup-v1,send-v1
```

Không đổi route/body Health/DTO, payload nghiệp vụ, event/consumer factory; 189 runtime paths giữ nguyên. Client kiểm handshake trước credential và mỗi mutation, gồm lookup; B19 ACK/rejection proof vẫn giữ nguyên. Deploy server có header trước client mới. Thư viện/test client có thể không bật gate; entrypoint được hỗ trợ bắt buộc bật.

Không thêm/sửa PostgreSQL 001–024 hoặc SQLite 001–003. Cache v1/v2 vẫn đi qua backup/migration B19; preflight chỉ đọc, từ chối revision >3 hoặc corrupt/FK lỗi. Giữ partition theo server/user/device và SENDING→UNKNOWN trên lần mở journal tiếp theo.

Hook dùng chung cần điều phối review:

- `apps/server/api/app.py`: hai health headers, không mở route mới.
- `apps/desktop/api/client.py`, `identity.py`, `__main__.py`, `printing/spool.py`: gate, startup và frozen helper.
- `apps/server/infrastructure/file_storage.py` + module `private_files.py`: xử lý Windows thiếu O_NOFOLLOW (#21). Linux giữ no-follow/0600/fsync. Windows dùng CreateFileW OPEN_REPARSE_POINT, kiểm attributes trước chuyển handle thành fd, DACL protected owner+SYSTEM khi tạo. Directory fsync không áp dụng Windows; production server vẫn Linux.
- Test storage cũ giữ kiểm hash/immutable/symlink, kiểm DACL thật trên Windows và mode0600 trên Linux; không skip/xóa test. **Nhánh Win32 chưa chạy**, cần hosted Windows xác nhận #21, không tự nhận issue đã đóng.
- `SHA256SUMS.txt` sinh bằng script repo; tài liệu tiến độ/tổng nghiệm thu không sửa.
